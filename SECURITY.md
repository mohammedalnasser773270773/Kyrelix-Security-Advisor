# Security Policy

## Reporting a Vulnerability

Kyrelix Security Advisor supports security-sensitive workflows. **Do not disclose suspected vulnerabilities or proof-of-concept details through public issues, pull requests, or discussions.** Never include passwords, TOTP/HOTP secrets, recovery codes, OAuth tokens, backup files, private device information, or personally identifiable user data.

**Preferred method:** Use **Security → Report a vulnerability** in this repository **if GitHub Private Vulnerability Reporting is enabled**.

If this option is not available, do not publish the vulnerability publicly. Use a verified private contact channel after the project owner has announced one.

A useful report should include:

1. The affected application version and relevant environment.
2. A concise explanation of the behavior and possible security impact.
3. Steps to reproduce using test accounts or sanitized data only.
4. Supporting evidence with any secrets and personal information removed.

Do not test other people's accounts, third-party services, or systems without permission.

## Scope

This policy concerns security issues in the Kyrelix application and the project's published assets. It does not authorize testing of Google, GitHub, Microsoft, Appwrite, or any other provider.

## Responsible Disclosure

No formal bug-bounty program, guaranteed response time, or disclosure deadline is currently announced. If such commitments are adopted, they will be documented explicitly here.
